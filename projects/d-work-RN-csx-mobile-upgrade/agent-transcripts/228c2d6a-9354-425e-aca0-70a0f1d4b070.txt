## 三、月度 Token 用完后会怎样？

### 方式一：开启按需用量（On-Demand Usage）

- 在 Billing 页面**开启 On-Demand Usage** 后，超出包含额度会按 API 价格额外计费
- 可在编辑器内继续使用，不会中断
- 额外费用会出现在「On-Demand Usage」中

### 方式二：不开启按需用量

- 当 On-Demand Usage 为**关闭**时，达到 100% 月度额度后：
  - 可能被**限流**或暂时无法使用高级模型
  - 可能降级到较慢/较小的模型
  - 直到下个账单周期重置额度

### 建议

1. 定期查看：https://cursor.com/cn/dashboard?tab=usage  
2. 如不希望意外扣费，可保持 On-Demand Usage **关闭**  
3. 快接近额度时，可少用高消耗模型（如 thinking 模型）

## 五、Win11 Cursor 全局配置目录相关问题

### 全局配置位置

- Win11 下，Cursor 的全局配置主要在：`C:\Users\Stark8964911\AppData\Roaming\Cursor`
- 该目录包含：settings.json、缓存、扩展、日志等大量文件

### 为什么用 Cursor 打开该目录会卡住/黑屏？

1. **文件数量多**：  
   - 目录树显示约 **55,000+ 文件**（含 CachedData、extensions 等子目录）  
   - Cursor 基于 VSCode，打开时会索引、扫描所有文件，体量过大会导致加载缓慢甚至卡死  

2. **缓存与索引开销大**：  
   - 目录内有 Cache、CachedData、GPUCache 等  
   - 编辑器和扩展会尝试读取并索引这些文件，加重负担  

3. **工作区加载超时**：  
   - 大工作区会触发大量文件系统操作和语言服务/扩展的初始化  
   - 容易出现长时间黑屏、无响应

### 优化建议

1. **改用「文件」打开而不是作为工作区**  
   - 需要浏览该目录时，用 **Windows 文件资源管理器**  
   - 或在 Cursor 中用「文件 > 打开文件」打开单个文件，而不是「打开文件夹」  

2. **只打开必要的子目录**  
   - 例如只打开 `User` 目录编辑 `settings.json`  
   - 路径：`C:\Users\Stark8964911\AppData\Roaming\Cursor\User`  

3. **在 .cursorignore 中排除大目录（若作为项目使用）**  
   - 若必须把该目录作为项目打开，可在项目根目录添加 `.cursorignore`  
   - 排除：`Cache`、`CachedData`、`GPUCache`、`blob_storage` 等大目录  

4. **定期清理缓存**  
   - 可关闭 Cursor 后，手动删除 `Cache`、`CachedData`、`Code Cache` 等目录  
   - 下次启动时会重新生成，可能会加快打开速度  

5. **用脚本/命令行编辑**  
   - 修改 `settings.json` 等配置时，可用 PowerShell 或记事本直接编辑，避免通过 Cursor 打开整个目录
