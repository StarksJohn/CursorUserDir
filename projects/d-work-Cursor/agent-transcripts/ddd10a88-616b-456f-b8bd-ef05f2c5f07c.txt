## 四、composer-1.5 为何不计入 Billing 中的 Usage 百分比

**原因：** composer-1.5 属于 **Auto + Composer** 类别，有独立的使用额度，不来自 $70 API agent usage 预算。

- Usage 页面显示 composer-1.5 的 Cost 列为 **"Included"**（包含在内）
- Billing 页面 "Auto + Composer" 行显示 **0 tokens / 0.0%**

这说明 Cursor 对 composer-1.5 的 token 消耗采用完全独立的计量体系，不与高级 API 模型共享月度 $70 额度。**因此 composer-1.5 的使用不会"消耗"你的月度 API 百分比。**

## 五、月度 token 用完后的处理方式

当月度 API 额度（约 $110~$115）耗尽后：

| 模型类型 | 用完后是否可用 | 说明 |
|---|---|---|
| claude-4.6-sonnet-medium-thinking | 需额外付费 | 触发 On-Demand 按需计费 |
| claude-4.6-opus-high-thinking | 需额外付费 | 触发 On-Demand 按需计费 |
| **composer-1.5** | **可继续免费使用** | 不来自 API 额度，独立提供 |

### On-Demand 按需计费规则

- 费率与 Included 用量**相同**（不涨价，不降质）
- 需要在账户中预存信用额度（Credit）才能使用
- 在编辑器中会有用量超限提醒
- 超出后可选择：①升级更高计划 ②开启按需付费继续使用

### 实际建议

如果当月额度用完但仍需使用高级模型，可直接切换到 **composer-1.5** 继续工作，因为它有独立的免费额度且功能强大（200k context window）。
