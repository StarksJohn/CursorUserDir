**superguineapig** commented on 2025-08-14T22:24:13Z:

> ### General notes for others
> 
> I'm really not familiar enough with the ReactNative build process to go much further in figuring out **where a proper solution lies** i.e. 
> - a bug with ReactNative 0.81.x itself (ReactCommon and/or ReactFabric module)
> - a change in the ReactNative native modules API for library developers
> - a missing framework header path in `react-native-reanimated/worklets`
> - or some compiler directive/pragma needed to "detect" RN 81 and static linking
> 
> For now, it seems ok to use RN 0.80.2 to keep existing projects working. However, I suspect that this issue will start cropping up more and more for others who are using `static linking` in their Podfile.
> 
> #### Speculation
> 
> Looking at the change logs between RN 0.80.2 and 0.81.x does reveal that there are changes to header paths and the output of building the `ReactCommon` package. I can only surmise that perhaps RN is in the process of changing their development API for native module developers. (or accidental omission of build outputs?)
> 
> ### Some findings
> 
> ##### not library specific
> 
> It should be noted that this is **NOT** an issue with `react-native-firebase` itself, as the build error will manifest itself simply by setting the linking directive:
> 
> ```
> use_frameworks! :linkage => :static
> ```
> 
> And given that `react-native-firebase` requires that linking be set to static, it is expected that coincidentally many of those projects also using `react-native-reanimated` on RN 0.81.x will encounter this problem. These are both very common and popular libraries.
> 
> ##### not isolated to either 3.x or 4.x of reanimated
> 
> Both 3.x and 4.x versions of `react-native-reanimated` are affected. The common thread is **RN 0.81.x with static linking (iOS Podfile)**
> 
> Either way, in 81.x with statically linked frameworks, the ReactCommon module/framework artifact does not expose a necessary header file that is referenced by *other react native code* <-- the compiler error is at the bottom of an include chain of several files in `ReactCommon`
> 
> ```
> (reanimated v4.x) WorkletsModuleProxy.cpp - #include 
> - (react native) UIManagerBinding.h - #include 
> - (react native) UIManager.h - #include <-- ERROR
> 
> or
> 
> (reanimated 3.x) JSScheduler.h - #include <-- ERROR: directly references the missing file
> ```
> Perhaps there is a different configuration necessary for consumers of ReactNative API in 0.81.x (specifically when statically linked) or it's a bona fide bug with React Native.
> 
> ### Final thoughts
> 
> I get the sense that this is going to be a significant issue for others and it will involve some collaboration across the RN community to see a resolution as it will probably manifest itself from other libraries as well...chaos ensues 🥸
> 
> Unfortunately, I'm not familiar enough with all of the pieces involved to go much further with troubleshooting. Though I'm happy to help if I can.
> 
> @mikehardy sorry for the unsolicited tag, but I suspect you may be hearing whispers of this in the future, so this is just a friendly "something to be aware of"
