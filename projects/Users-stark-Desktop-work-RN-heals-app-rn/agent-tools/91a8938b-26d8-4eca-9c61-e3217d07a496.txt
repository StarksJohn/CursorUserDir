## huntie Sep 4, 2024 Maintainer

## Introduction

In React Native 0.76, we're shipping the first stable release of React Native DevTools, our new debugging experience for React Native apps using Hermes.

React Native DevTools features:

- A completely rebuilt debugger architecture, including an all-new CDP backend, designed for reliability and correctness.
- Familiar, web-aligned tooling — An integrated frontend with familiar features from Chrome DevTools that work as they do on web, as well as the React DevTools Element Inspector and Profiler.
- A cohesive and refined experience — React Native DevTools is set up by default with zero config. Open from the Dev Menu or via`j` to debug in the CLI server. See a new “Paused in Debugger” overlay and simplified LogBox states while debugging.

React Native DevTools is designed for debugging React app concerns, and not to replace native tools. If you want to inspect React Native’s underlying platform layers (for example, while developing a Native Module), please use the debugging tools available in Xcode and Android Studio.

Tip

Learn more about React Native DevTools in the 0.76 release blog post or the announcement talk 🎬.

## Compatibility

React Native DevTools supports all React Native 0.76 apps running Hermes. It replaces the previous Flipper, Experimental Debugger, and Hermes debugger (Chrome) entry points.

It is not possible to set up React Native DevTools with any older versions of React Native.

Chrome Browser DevTools — unsupported

- Connecting to React Native via`chrome://inspect` is no longer supported. Features may not work correctly, as the latest versions of Chrome DevTools (which are built to match the latest browser capabilities and APIs) have not been tested, and this frontend lacks our customisations. Instead, we ship a supported version with React Native DevTools.

Visual Studio Code — unsupported (pre-existing)

- Third party extensions such as Expo Tools and Radon IDE may have improved compatibility, but are not directly supported by the React team.

## Available debugging options from 0.76

- React Native DevTools (default)
- Remote JavaScript Debugging (deprecated)
- Safari Developer Tools (Direct JSC Debugging)

If you are using a debugging option other than React Native DevTools, this will not be connected to the React Native DevTools backend, and therefore issues should be raised outside this discussion thread.

## Related deprecations in 0.76

- The standalone build of React DevTools (`npx react-devtools`) will no longer work with 0.76, and this entry point is deprecated.

## FAQs

React Native DevTools is fundamentally separate from the previous “Experimental Debugger” (React Native 0.73-0.75). Please use the previous thread if you see the old frontend.

How do I know if I’m on React Native DevTools?

- After launching DevTools from the Dev Menu or CLI, you should land on a welcome panel saying “React Native DevTools” (NOT "React Native JS Inspector").
- A highlighted log saying`Welcome to React Native DevTools` should be printed to the console.

When is React Native DevTools coming to Expo?

React Native DevTools should land in Expo in the next Expo SDK that aligns with React Native 0.76, so long as Expo is happy with end to end compatibility. At time of writing, this will be SDK 52.

How do I use the Network panel?

React Native DevTools does not ship with Network inspection as of 0.76. We are aware this is a highly-requested feature. First party support, built into our new C++ debugger stack, is work in progress and will ship in a future release.

Alternatives:

- Network panel under Expo: Supported in Expo since SDK 49. This implementation is built outside of the React Native DevTools stack, but we've exposed a "Network (Expo, unstable)" panel in our frontend.
- Use third party tools such as Reactotron, Charles Proxy.

How do I use third party Chrome extensions?

React Native DevTools does not ship with support for loading third party Chrome extensions (such as Relay DevTools or Redux DevTools) as of 0.76. This is a feature that conceptually fits what we want to offer, but is further out in our plans.

We are in early exploration on this feature, in partnership with Expo. We want JS dev plugins in React Native DevTools to share the same reliable debugger connection as the rest of our infra, and we want to design the necessary APIs for this precisely. Another concern will be how we safely load 3P extension code and meet our quality bar. Prior art such as Expo Dev Plugins may inform us about how we make third party plugins loadable into DevTools.

Alternatives:

- Expo Dev Plugins are an existing solution for loading a number of third party DevTools plugins in an out-of-tree manner.
- react-native-debugger is a community project that includes built in DevTools plugins for popular third party JavaScript libraries. (Note: This will eject out of the React Native DevTools backend and to Remote JavaScript Debugging.)

Why are JavaScript logs leaving Metro?

We want every aspect of React Native debugging to behave reliably, and to match the functionality of modern browser tooling. To meet this quality bar, we are removing log forwarding via Metro in 0.77, with a warning logged today.

Web alignment, separation of concerns: Application logs in Metro pollute the primary information logged by Metro/the dev server, such as when bundles are sent to a device. No other bundlers replicate this functionality.

- For a web app, you wouldn’t forward logs in the dev server. Instead, these tools only log bundle requests, and you go to a particular instance of the webpage/app to open the browser DevTools.

Please use React Native DevTools and its fully featured Console panel — supporting log filtering, rich object inspection, and Live Expressions.

If you really want to view inline logs in your IDE, the modern approach would be to consider one of the third party VS Code offerings, which stream logs over CDP.

When will we remove Remote JavaScript Debugging?

No time soon(!). This debugging mode remains deprecated, but we appreciate the use case for third party Chrome extensions. Remote JavaScript Debugging won't stay around forever — but we'll consider down the line if we've replaced enough of its functionality (or this functionality is implemented robustly by frameworks), to remove it.

What features are coming next?

- Performance panel (+ profiling builds support): In progress (targeting next year).
- Network panel: In progress (targeting next year).
- Third party Chrome extensions: In early exploration, in collaboration with Expo (no ETA).

#### huntie Nov 4, 2024 Maintainer Author

Sure (I use Arc as well!). As@sntg-p mentioned, you can try setting CHROME_PATH, however Arc's launch behaviour is different to base Chromium and I don't think this will work.

Instead, try this workaround (power users only) — paste the following URL into your browser (assuming Metro is running at localhost:8081), and it will redirect to React Native DevTools.

```
http://localhost:8081/open-debugger

```

Note that this approach is unstable and unsupported:

- A`GET` request to this URL will only work if there is exactly one device connected to Metro. Additionally, this URL may work differently/break in future RN versions.
- We don't officially support browsers other than Google Chrome or Microsoft Edge.

In future, we're looking at packaging React Native DevTools so that it doesn't require an external browser at all.

#### huntie Jan 24, 2025 Maintainer Author

@jehillert I hear your feedback.

The main thing here is that, unfortunately, react-native-debugger has been relied upon without being updated to work with any of React Native's modern debugging options. In the meantime, alternatives and standalone workflows for dev integrations such as Redux DevTools have emerged.

#### Background

- It's worth noting that third-party dev plugins have always been adjacent to our core debugger offering (not directly offered or supported by the React team).
- react-native-debugger is a community project that has composed these together (rightly celebrated at the time!), but also has been architecturally tied to Remote JS Debugging and has not moved forward. React Native has provided a CDP-based debugging backend for >4 years (since Hermes as the default engine).

Today, tools like Expo DevTools Plugins are the way to handle third party developer tools. Expo includes a documented setup flow for Redux DevTools. (I appreciate that not all React Native apps have moved to Expo yet — but a brownfield setup is possible.)

- Notable: Every previous DevTools plugin via react-native-debugger communicated via a separate WebSocket connection — this is exactly what the Expo/Radon IDE solutions do now.
- Redux DevTools documents a remote integration setup, which can be combined with the`@redux-devtools/cli` launcher.
- With either of these packages, it's possible for development teams to set up a Redux DevTools launch flow for their project, and expose them to other developers via an npm script.

#### Other ways forward

The only realistic future for react-native-debugger is the WIP effort to migrate to CDP. We're happy to answer questions if this effort resumes and blockers are encountered — but it is more than likely that the existence of the other solutions means the work is now unjustified.

- Plan: New Hermes/RNV8 debugger support jhen0409/react-native-debugger#774.

---

The bottom line: Remote JS Debugging was fundamentally a debugging method at odds with React Native's architecture. We will be removing Remote JS Debugging in React Native 0.79, following Expo already having dropped support in SDK 52.

- [0.79] Removal of Remote JS Debugging via Chrome #872

And we do, aspirationally, want to offer more in React Native DevTools, such as select 3P dev plugins. We need to be careful how we do this, for stability/future maintainability.

I think we've communicated around: if you're not using a React Native framework (like Expo), you are maintaining your own framework [1].
