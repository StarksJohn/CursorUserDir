**Describe the bug** 
Whilst running our android test folder containing 70~ flows taking around 40mins on CI, the below `Exception in thread "pool-4-thread-1"` occurs. This then causes an execution timeout, stopping the build on agent. 
```
  Exception in thread "pool-4-thread-1" java.io.IOException: Command failed (host:transport:emulator-5554): device 'emulator-5554' not found
    at dadb.adbserver.AdbServer.send$dadb(AdbServer.kt:99)
    at dadb.adbserver.AdbServerDadb.open(AdbServer.kt:137)
    at dadb.forwarding.TcpForwarder.handleForwarding$lambda-1(TcpForwarder.kt:64)
    at java.base/java.util.concurrent.ThreadPoolExecutor.runWorker(ThreadPoolExecutor.java:1136)
    at java.base/java.util.concurrent.ThreadPoolExecutor$Worker.run(ThreadPoolExecutor.java:635)
    at java.base/java.lang.Thread.run(Thread.java:833)
```
**To Reproduce** 
1. Running the emulator headless on CI 
2. Run a test folder containing a large number of flows 
3. The Flow fails around the 40 min mark because of the `Exception in thread "pool-4-thread-1" java.io.IOException: Command failed (host:transport:emulator-5554): device 'emulator-5554' not found` 
 
**Expected behaviour** 
The adb server to continue running after lengthy execution times. 
 
**Environment information:** 
- Maestro version [v1.33.1] 
- Platform: [Android 13] 
- Framework: [Native Android] 
- Emulator - headless 
- Host [AWS linux-x86_64]

**DavidREntwistle** commented on 2025-02-21T13:07:10Z:

> I think this [issue](https://github.com/mobile-dev-inc/maestro/issues/1525) could be caused by the Android System Image being in a read-only state and not a writable state.
> 
> This emulator launch command on CI seems to have resolved this issue for us:
> `"${ANDROID_HOME}/emulator/emulator" -avd "yourEmulatorDeviceNameHere" -cores 4 -memory 8192 -camera-front emulated -camera-back emulated -gpu swiftshader_indirect -no-window -verbose -no-audio -show-kernel -no-boot-anim -writable-system &` 
> 
> Main flags:
> - By default, the emulators use x2 cores, doubling the CPU to try to help - `-cores 4`
> - Ensure that we have a reasonable amount of RAM, most modern pixel devices are around this - `-memory 8192`
> - Ensure that the system image is in a writable state, even with `-read-only` omitted, the emulator would launch in a `-read-only` state. Enabling this `-writable-system` should allow app caching, and data persistence on the Android emulator's local storage, possibly resulting in emulator issues if this isn't the case.

**lucaslannes** commented on 2025-03-20T21:18:46Z:

> Hello, everyone!
> 
> I spent about 2 to 3 weeks setting up Azure Pipelines to run an Android emulator and execute automated tests using Maestro.
> 
> As some have already mentioned, it is possible to run an Android emulator with API 28 (I also managed to do it with API 26).
> 
> However, in the project I am working on, it was necessary to run automated tests on a more recent Android version (API 30 or higher, preferably).
> 
> After many attempts and errors, we managed to stabilize the pipeline using API 33 by implementing the following changes:
> 
> 1. We used a lower-resolution emulator, 4.65in 720p (Galaxy Nexus).
> 2. We removed the `google_apis` package when creating the emulator.
> 
> The final sequence of commands is:
> 
> ```sh
> # Install required packages to create and run the Android emulator
> echo "y" | sdkmanager --install 'system-images;android-33;default;x86_64'
> 
> # Create the Android emulator
> echo "y" | avdmanager create avd -n android -d "4.65in 720p (Galaxy Nexus)" -k 'system-images;android-33;default;x86_64' --force
> 
> # Run the Android emulator
> nohup emulator -avd android -no-snapshot -no-window -no-audio -no-boot-anim -camera-back none -camera-front none -qemu -m 2048 > /dev/null 2>&1 &
> ```
> 
> You can check out a more detailed step-by-step guide in an article I wrote:
> 
> https://codenergy.dev/articles/running-the-android-emulator-on-cicd-pipelines
