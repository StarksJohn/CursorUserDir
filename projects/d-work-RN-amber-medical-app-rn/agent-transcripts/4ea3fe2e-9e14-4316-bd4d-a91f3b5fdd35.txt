**在 `useCallback` 的回调里调用 `useState` 不符合 React Hooks 规则，应避免这样写。**

### 1. 违反 Hooks 规则

React 的 [Rules of Hooks](https://react.dev/reference/rules/rules-of-hooks) 明确要求：

- **不要在嵌套函数中调用 Hooks**：传给 `useCallback` 的函数属于嵌套函数，在其中调用 `useState` 属于违反规则。
- **只在顶层调用 Hooks**：Hooks 应在组件或自定义 Hook 的顶层、且以稳定顺序调用。

当前写法：

```tsx
const SecondRoute = useCallback(
  () => {
    const [refresh, setRefresh] = useState(false);  // Line 227 - Violates Rules of Hooks
    return (
      <FlatList ... />
    )
  },
  [data],
);
```

`useState` 被放在了 `useCallback` 的回调内部，属于「在嵌套函数中调用 Hook」，不符合规范。

### 2. 与 FirstRoute 不一致

对比 `FirstRoute`（约 146–174 行）：内部的 `useState` 已被注释，改为使用组件顶层定义的 `refresh`：

- 第 36 行：`const [refresh, setRefresh] = useState(false);`
- `FirstRoute` 的 `FlatList` 直接使用该 `refresh`。

而 `SecondRoute` 在内部又声明了新的 `refresh`，两个 Tab 的刷新状态不统一，也不符合「在组件顶层管理状态」的写法。
