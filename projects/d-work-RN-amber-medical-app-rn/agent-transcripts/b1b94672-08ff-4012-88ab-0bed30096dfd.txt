## 修复总结

### 1. 第 62 行及 API 数据处理（控制台报错）
- **问题**：当 API 返回 `undefined` 或非数组时，`setData(res)` 会导致后续 `data.filter` 报错：`"filter is not a function"`。
- **修复**：
  - 用 `try/catch` 包住 `getData`；
  - 确保始终设置数组：`const list = Array.isArray(res) ? res : []`；
  - 异常时执行 `setData([])`，避免渲染阶段再报错。

### 2. `displayName` 导致的崩溃
- **问题**：`item?.product?.displayName.split(" (")[0]` 在 `displayName` 为 `null`/`undefined` 时会在 `split` 上报错。
- **修复**：改为 `(item?.product?.displayName ?? '').split(' (')[0]`，保证对空值安全。

### 3. 激活记录索引错误（页面显示异常）
- **问题**：`renderFirstRouteItem` 先 filter 出未激活记录，再用 `itemNo` 作为索引访问原始 `activationRecords`，导致索引错位、显示错误激活状态或错误激活码。
- **修复**：直接传入 `activationRecord` 给 `renderPlansPerItem(item, activationRecord)`，不再使用索引；`renderPlansPastItem` 也改为直接使用 `item`。

### 4. 空值防护
- 对 `activationRecords` 使用 `|| []`；
- 对 `item?.product?.duration` 使用可选链，避免访问 `undefined` 导致崩溃。

### 5. React key
- 使用 `activationRecord.id` 或 `item.id + index` 作为列表项 key，避免重复 key 导致的渲染问题。
