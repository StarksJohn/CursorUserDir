## 问题背景

Amber Medical App 在 Google Play Console 收到 **16KB memory page sizes** 兼容性警告。从 **2025年11月1日** 起（截止日期已延长至 **2026年5月31日**），所有针对 Android 15+ 的新应用和更新都必须支持 16KB 页面大小。

### 问题根源

React Native 0.76.3 的核心原生库（`.so` 文件）在编译时使用 4KB 页面对齐，不满足 Android 15+ 要求的 16KB 对齐。这是一个 **React Native 框架级别** 的问题，无法通过简单配置修改解决，必须升级 React Native 到 0.77+ 版本。

### 关键时间节点

- **Google Play 截止日期**: 2026年5月31日
- **React Native 0.77 发布**: 2025年1月（首个内置 16KB 支持的版本）
- **React Native 0.81+**: 推荐的目标升级版本

---

## 问题背景

Amber Medical App 在 Google Play Console 收到 **16KB memory page sizes** 兼容性警告。从 **2025年11月1日** 起（截止日期已延长至 **2026年5月31日**），所有针对 Android 15+ 的新应用和更新都必须支持 16KB 页面大小。

### 问题根源

React Native 0.76.3 的核心原生库（`.so` 文件）在编译时使用 4KB 页面对齐，不满足 Android 15+ 要求的 16KB 对齐。这是一个 **React Native 框架级别** 的问题，无法通过简单配置修改解决，必须升级 React Native 到 0.77+ 版本。

### 关键时间节点

- **Google Play 截止日期**: 2026年5月31日
- **React Native 0.77 发布**: 2025年1月（首个内置 16KB 支持的版本）
- **React Native 0.81+**: 推荐的目标升级版本

---

### 第三阶段：Google Play 首次上传 - 失败 (Does not support 16 KB)

将 `app-prod-release.aab` 上传到 Google Play Console 内部测试轨道后，App Bundle Explorer 显示：

> **Memory page size: Does not support 16 KB**
> Library that does not support 16 KB: **base/lib/x86_64/libconceal.so**

#### 根本原因分析

AAB (Android App Bundle) 打包了 **所有架构** 的 .so 文件：
- arm64-v8a (通过 16KB 验证)
- armeabi-v7a
- armeabi
- x86
- **x86_64** (libconceal.so 未对齐 16KB)

虽然本地只验证了 arm64-v8a（全部通过），但 Google Play 会检查 AAB 中 **所有架构** 的 .so 文件。`x86_64/libconceal.so`（来自 Fresco/Conceal 加密库）没有 16KB 对齐，导致不通过。

#### 关键发现

- `splits.abi` 只控制 **APK 分包**，不控制 **AAB 打包内容**
- AAB 会包含所有架构，由 Google Play 根据设备分发
- 必须使用 `ndk.abiFilters` 限制 AAB 中包含的架构
- `ndk.abiFilters` 和 `splits.abi` **不能同时使用**（会报 Conflicting configuration 错误）

### 第四阶段：限制 AAB 只包含 arm64-v8a - 解决问题

#### 4.1 修改 gradle.properties

```properties
# Before:
reactNativeArchitectures=armeabi-v7a,arm64-v8a

# After:
# Only build for arm64-v8a to ensure 16KB page size compliance
# x86/x86_64 are emulator-only and some libs (libconceal.so) lack 16KB alignment
reactNativeArchitectures=arm64-v8a
```

#### 4.2 修改 android/app/build.gradle

**移除 `splits` 配置，改用 `ndk.abiFilters`：**

```groovy
// Before:
defaultConfig {
    applicationId "com.ambermedicalapp"
    // ...
}
splits {
    abi {
        enable true
        reset()
        include 'armeabi-v7a', 'arm64-v8a'
        universalApk true
    }
}

// After:
defaultConfig {
    applicationId "com.ambermedicalapp"
    // ...
    // Restrict to arm64-v8a only for 16KB page size compliance
    // x86_64/libconceal.so does not support 16KB alignment
    ndk {
        abiFilters 'arm64-v8a'
    }
}
// splits 配置已移除
```

**清理 packagingOptions 中不再需要的 x86/x86_64 pickFirst 规则：**

```groovy
// Before:
packagingOptions {
    pickFirst 'lib/x86/libc++_shared.so'
    pickFirst 'lib/x86_64/libjsc.so'
    pickFirst 'lib/arm64-v8a/libjsc.so'
    pickFirst 'lib/arm64-v8a/libc++_shared.so'
    pickFirst 'lib/x86_64/libc++_shared.so'
    pickFirst 'lib/armeabi-v7a/libc++_shared.so'
    jniLibs { useLegacyPackaging = false }
}

// After:
packagingOptions {
    // Only arm64-v8a needed for 16KB page size compliance
    pickFirst 'lib/arm64-v8a/libjsc.so'
    pickFirst 'lib/arm64-v8a/libc++_shared.so'
    jniLibs { useLegacyPackaging = false }
}
```

## 踩坑要点总结

### 1. 本地验证通过 ≠ Google Play 验证通过

本地使用 `check_16kb_alignment.ps1` 只检查了 arm64-v8a APK 中的 .so 文件（46 个全部通过），但 **AAB 包含所有架构**。Google Play 会检查 AAB 中每个架构下的每一个 .so 文件，包括 x86_64。

**教训：** 验证时不仅要检查 arm64-v8a，还要验证 AAB 中包含的所有架构，或者直接限制 AAB 只包含 arm64-v8a。

### 2. splits.abi 不控制 AAB 内容

`splits.abi` 只控制 **APK 分包策略**（生成哪些架构的 APK），**不限制 AAB 打包哪些架构的原生库**。要限制 AAB 中的架构，必须使用 `defaultConfig.ndk.abiFilters`。

### 3. ndk.abiFilters 和 splits.abi 冲突

两者不能同时使用，否则 Gradle 会报错：
> Conflicting configuration: 'arm64-v8a' in ndk abiFilters cannot be present when splits abi filters are set

**解决方案：** 移除 `splits` 配置块，只使用 `ndk.abiFilters`。

### 4. 只保留 arm64-v8a 是安全的

现代 Android 手机全部是 arm64-v8a 架构。移除 x86/x86_64（模拟器）和 armeabi-v7a（32位老设备）不会影响实际用户。Google Play 显示设备数减少（18,427 -> 12,241）主要是排除了模拟器和极旧设备。
