    fix: restore the iOS biometric switch after returning from Settings
    
    Account Security shows a "to open" row when Face ID permission was denied and isSensorAvailable reports that the fingerprint scanner is not available. Tapping that row opened Settings with the private app-settings: URL and immediately cleared the Face ID and fingerprint flags. Returning to the app only refreshed calendar permission, so biometryType stayed empty and the Face ID switch never replaced the "to open" row until the page was left and opened again.
    
    Track when the iOS app has entered inactive or background, then call the existing loadBiometricSettings when it becomes active again. Skip that reload on the first active state because mount already loads biometrics, which avoids two overlapping sensor checks on entry. Android returns immediately from this effect, and the settings row remains iOS-only. Opening Settings now uses Linking.openSettings(), and the row no longer clears biometric flags itself; the foreground reload decides whether to show the switch or keep the settings row.
    
    Also commit the already staged empty ios/.metro-host.local file. It has no content and is not referenced by the app.
