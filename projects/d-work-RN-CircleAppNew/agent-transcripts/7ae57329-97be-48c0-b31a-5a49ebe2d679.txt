## 问题背景

CircleApp 在 Google Play Console 上传 AAB 后收到 **16KB memory page sizes** 兼容性错误。从 **2025年11月1日** 起（截止日期已延长至 **2026年5月31日**），所有针对 Android 15+ 的新应用和更新都必须支持 16KB 页面大小。

### Google Play 报错信息

```
Libraries that do not support 16 KB:
base/lib/arm64-v8a/libHealthyMonitor.so
base/lib/arm64-v8a/libabsl.cr.so
base/lib/arm64-v8a/libbloodsuger.so
base/lib/arm64-v8a/libbodytemp.so
base/lib/arm64-v8a/libc++_chrome.cr.so
base/lib/arm64-v8a/libc++_shared.so
base/lib/arm64-v8a/libchrome_zlib.cr.so
base/lib/arm64-v8a/libfbjni.so
base/lib/arm64-v8a/libhermes.so
base/lib/arm64-v8a/libhermestooling.so
base/lib/arm64-v8a/libicuuc.cr.so
base/lib/arm64-v8a/libimagepipeline.so
base/lib/arm64-v8a/libjsi.so
base/lib/arm64-v8a/liblibox.so
base/lib/arm64-v8a/libnative-filters.so
base/lib/arm64-v8a/libnative-imagetranscoder.so
base/lib/arm64-v8a/liboxygen.so
base/lib/arm64-v8a/libpartition_alloc.cr.so

base/lib/x86_64/libHealthyMonitor.so
base/lib/x86_64/libNskAlgo.so
... (以及更多 x86_64 库)
```

### 问题根源

React Native 0.76.3 的核心原生库（`.so` 文件）在编译时使用 4KB 页面对齐，不满足 Android 15+ 要求的 16KB 对齐。这是一个 **React Native 框架级别** 的问题，无法通过简单配置修改解决，必须升级 React Native 到 0.77+ 版本。

### 不合规库分类

| 类别 | 库文件 | 来源 |
|------|--------|------|
| RN 核心 | libhermes.so, libhermestooling.so, libjsi.so, libreactnative.so | React Native 0.76.3 |
| RN 生态 | libreanimated.so, librnscreens.so, libworklets.so | react-native-reanimated, screens |
| Fresco | libfbjni.so, libimagepipeline.so, libnative-filters.so, libnative-imagetranscoder.so | Facebook Fresco (旧版) |
| PDF | libpdfium.cr.so, libpdfiumandroid.so, libabsl.cr.so, libc++_chrome.cr.so 等 | pdfiumandroid (旧版) |
| C++ | libc++_shared.so | NDK C++ 标准库 |
| 健康 SDK | libHealthyMonitor.so, libbloodsuger.so, libbodytemp.so | BleDev AAR (Linktop) |
| x86_64 独有 | libconceal.so, libNskAlgo.so, libneuroskybpi.so | Fresco/Conceal, NeuroSky SDK |

### 关键时间节点

- **Google Play 截止日期**: 2026年5月31日
- **React Native 0.77 发布**: 2025年1月（首个内置 16KB 支持的版本）
- **React Native 0.81+**: 推荐的目标升级版本

## 解决方案概览

基于 `amber-medical-app-rn` 项目的成功经验，解决方案分为以下阶段：

1. **升级 React Native** 0.76.3 -> 0.81.0（获得 16KB 对齐的核心库）
2. **升级 Android 构建工具链**（NDK 27.1, Gradle 8.13, AGP 8.7.3 等）
3. **添加 Fresco 3.6.0 和 pdfiumandroid 1.0.35**（16KB 对齐版本）
4. **限制 AAB 只包含 arm64-v8a**（排除 x86_64 不合规库）
5. **配置 16KB 页面大小相关 Gradle 属性**

### 第二阶段：限制 AAB 只包含 arm64-v8a

#### 2.1 修改 gradle.properties

```properties
# Before:
reactNativeArchitectures=arm64-v8a,x86_64

# After:
# Only build for arm64-v8a to ensure 16KB page size compliance
# x86/x86_64 are emulator-only and some libs (libconceal.so) lack 16KB alignment
reactNativeArchitectures=arm64-v8a
```

#### 2.2 修改 android/app/build.gradle

**修改 ndk.abiFilters：**

```groovy
// Before:
ndk {
    abiFilters  "arm64-v8a","x86_64"//,"armeabi-v7a"
}

// After:
// Restrict to arm64-v8a only for 16KB page size compliance
// x86_64/libconceal.so and other libs do not support 16KB alignment
ndk {
    abiFilters 'arm64-v8a'
}
```

**移除 cmake externalNativeBuild 配置：**

```groovy
// Before (已移除):
externalNativeBuild {
    cmake {
        arguments "-DANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON"
    }
}
// 此配置仅对 NDK r26 有效，升级到 NDK r27.1 + RN 0.81 后不再需要
```

**修改 packagingOptions：**

```groovy
// Before:
packagingOptions {
    jniLibs {
        useLegacyPackaging = true  // WRONG: compressed libs bypass alignment check
    }
}

// After:
packagingOptions {
    // Only arm64-v8a needed for 16KB page size compliance
    pickFirst 'lib/arm64-v8a/libjsc.so'
    pickFirst 'lib/arm64-v8a/libc++_shared.so'
    jniLibs {
        useLegacyPackaging = false  // Uncompressed + page-aligned
    }
}
```

#### 2.3 修改 AndroidManifest.xml

```xml
<application
    android:name=".MainApplication"
    android:extractNativeLibs="false"
    ...>
```

## 特殊注意事项：BleDev AAR (Linktop Health SDK)

CircleApp 使用了本地 AAR 文件 `BleDev_release_v2.7.1.aar`，其中包含以下原生库：
- `libHealthyMonitor.so`
- `libbloodsuger.so`
- `libbodytemp.so`

这些库在 Google Play 报错中出现在 arm64-v8a 列表中，说明它们也不支持 16KB 对齐。

### 可能的解决方案

1. **升级 RN 到 0.81.0 后重新验证**：RN 0.81.0 使用 NDK 27.1 编译，但 BleDev AAR 是预编译的，NDK 升级不会影响它。不过，升级后 Google Play 的检查行为可能有所不同。

2. **联系 Linktop 供应商获取更新版本**：请求提供使用 16KB 页面对齐编译的新版 BleDev AAR。

3. **如果 BleDev 仍不通过**：可以暂时使用 `useLegacyPackaging = true` 作为临时方案（压缩存储原生库可以绕过对齐检查），但这不是长期解决方案，Google Play 未来可能会更严格地检查。

> **建议：** 先按照本指南完成 RN 升级和其他配置修改，构建 AAB 后上传到 Google Play Console 验证。如果 BleDev 的 .so 文件仍然不通过，再联系供应商获取更新版本。

## 踩坑要点总结

### 1. React Native 0.76.3 无法通过配置修复 16KB 问题

RN 0.76.3 的核心库（libhermes.so, libreactnative.so 等）是用 4KB 对齐编译的。cmake 参数 `ANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON` 和 `useLegacyPackaging = true` 都不是真正的解决方案：
- cmake 参数只影响项目自身的 C++ 代码编译，不影响预编译的 RN 库
- `useLegacyPackaging = true` 只是压缩存储绕过检查，不是真正的 16KB 对齐

**唯一的根本解决方案是升级 React Native 到 0.77+。**

### 2. useLegacyPackaging 的正确设置

| 设置 | 效果 | 16KB 兼容 |
|------|------|-----------|
| `useLegacyPackaging = true` | 原生库压缩存储，运行时解压到 data 目录 | 可能绕过检查但不推荐 |
| `useLegacyPackaging = false` | 原生库未压缩存储，直接从 APK 内存映射 | 需要 16KB 对齐，推荐 |

### 3. 只保留 arm64-v8a 是安全的

现代 Android 手机全部是 arm64-v8a 架构。移除 x86_64（模拟器）不会影响实际用户。Google Play 显示设备数减少主要是排除了模拟器设备。

### 4. 本地验证通过不等于 Google Play 验证通过

本地验证只检查特定架构的 APK，但 AAB 可能包含所有架构。Google Play 会检查 AAB 中每个架构下的每一个 .so 文件。

**教训：** 验证时要确保 AAB 中只包含已验证通过的架构。

### 5. extractNativeLibs 和 useLegacyPackaging 的关系

- `extractNativeLibs="false"` (AndroidManifest.xml): 告诉系统不要从 APK 中提取原生库
- `useLegacyPackaging = false` (build.gradle): 告诉构建系统不要压缩原生库
- 两者需要配合使用，确保原生库以未压缩、页面对齐的方式存储

## 特殊注意事项：BleDev AAR (Linktop Health SDK)

CircleApp 使用了本地 AAR 文件 `BleDev_release_v2.7.1.aar`，其中包含以下原生库：
- `libHealthyMonitor.so`
- `libbloodsuger.so`
- `libbodytemp.so`
- `liblibox.so`
- `liboxygen.so`
