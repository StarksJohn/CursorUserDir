## 16KB 页面大小问题 - 完整分析与解决方案

### 问题概述

Google Play 从 2025 年 11 月 1 日起要求所有面向 Android 15 (API 35) 的应用必须支持 16KB 内存页面大小。你的 AAB 中包含大量不符合 16KB 对齐要求的 `.so` 原生库，导致上传被拒绝。

---

### 不合规库分类分析

我将报错中列出的 51 个 `.so` 文件按来源分为 **6 大类**：

| 类别 | 涉及的 .so 文件 | 来源 | 解决方式 |
|------|----------------|------|----------|
| **A. RN 核心** | `libreactnative.so`, `libhermes.so`, `libhermestooling.so`, `libjsi.so`, `libfbjni.so`, `libc++_shared.so` | react-native 0.76.3 | 升级 RN 到 0.77+ |
| **B. 图片管线** | `libimagepipeline.so`, `libnative-filters.so`, `libnative-imagetranscoder.so` | RN 内置 Fresco | 升级 RN 到 0.77+ |
| **C. 第三方 RN 库** | `libreanimated.so`, `libworklets.so`, `librnscreens.so` | reanimated / screens | 升级对应 npm 包 |
| **D. PDF 库** | `libpdfium.cr.so`, `libpdfiumandroid.so`, `libabsl.cr.so`, `libc++_chrome.cr.so`, `libchrome_zlib.cr.so`, `libicuuc.cr.so`, `libpartition_alloc.cr.so` | react-native-pdf 6.7.6 | 使用修复版本 |
| **E. Linktop SDK** | `libHealthyMonitor.so`, `libbloodsuger.so`, `libbodytemp.so`, `liblibox.so`, `liboxygen.so` | BleDev_release_v2.7.1.aar | 联系 Linktop 获取新版 |
| **F. 其他** | `libNskAlgo.so`, `libneuroskybpi.so`, `libconceal.so` (仅 x86_64) | Linktop AAR / Facebook Conceal | 见下方说明 |

---

### 解决方案 - 分阶段执行

#### 阶段 1: 升级 React Native 到 0.77 (解决 A + B 类)

这是最关键的一步，RN 0.77 **内置了 16KB 页面大小支持**。

**需要的变更：**

1. **升级 RN 和 React**
```bash
npm install react-native@0.77.1 react@18.3.1
```

2. **升级 NDK** (在 `android/build.gradle`)
```groovy
ndkVersion = "27.1.12297006"  // 从 26.1.10909125 升级到 r27
```
> 推荐使用 NDK r27，RN 0.77 官方支持。NDK r28 也可以。

3. **升级 Kotlin** (在 `android/build.gradle`)
```groovy
kotlinVersion = "2.0.21"  // RN 0.77 要求 Kotlin 2.0
```

4. **使用 Upgrade Helper 查看完整 diff**：
   https://react-native-community.github.io/upgrade-helper/?from=0.76.3&to=0.77.1

5. **注意 Breaking Changes**：
   - `console.log()` 不再通过 Metro 转发，需使用 React Native DevTools
   - Kotlin 2.0 可能影响原生模块代码
   - iOS 端需要添加 `RCTAppDependencyProvider`

#### 阶段 2: 升级第三方库 (解决 C 类)

| 包名 | 当前版本 | 目标版本 | 说明 |
|------|---------|---------|------|
| `react-native-reanimated` | 3.17.0 | **3.18.0+** | 3.18+ 支持 RN 0.77 和 16KB |
| `react-native-screens` | 3.35.0 | **4.x+** | 需要大版本升级 |

```bash
npm install react-native-reanimated@latest react-native-screens@latest
```

#### 阶段 3: 修复 react-native-pdf (解决 D 类)

react-native-pdf 6.7.6 的 pdfium 库不支持 16KB。有两个选择：

**选项 A - 使用 GitHub master 分支修复版**：
```json
"react-native-pdf": "git+https://github.com/wonday/react-native-pdf.git#b0b074fc60c86c4f2e10deab6676d7c2a15be43d"
```

**选项 B - 使用 patch-package 打补丁**：
从社区获取 16KB 兼容的 pdfium 二进制文件并通过 patch-package 替换。

**选项 C - 考虑替代方案**：
如果 react-native-pdf 持续不更新，可以考虑迁移到 `react-native-blob-util` + WebView 方案查看 PDF。

#### 阶段 4: Linktop Health SDK (解决 E + F 类)

这是**最棘手的部分**，因为这些 `.so` 文件打包在 `BleDev_release_v2.7.1.aar` 中，是预编译的二进制文件。

**必须做的事情：**
1. **联系 Linktop** (service@linktop.com) 请求提供支持 16KB 页面大小的新版 BleDev SDK
2. 告知他们需要使用 NDK r27+ 重新编译所有原生库

**临时替代方案（如果 Linktop 响应慢）：**

#### 关于 x86_64 架构

报错中有些库仅出现在 `x86_64` 下（如 `libNskAlgo.so`, `libneuroskybpi.so`, `libconceal.so`）。如果你的应用**只面向真实物理设备**（不需要模拟器），可以考虑：

在 `android/app/build.gradle` 中只保留 arm64：
```groovy
ndk {
    abiFilters "arm64-v8a"  // 去掉 x86_64
}
```
同时修改 `gradle.properties`：
```properties
reactNativeArchitectures=arm64-v8a
```

这样可以减少一部分不合规的库，但 arm64 下的库仍然需要修复。
