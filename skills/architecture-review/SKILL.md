# Architecture Review

## 触发场景

- 用户输入 `@architecture-review` 或提及“架构评审”“模块边界”“系统设计”
- 重大重构前的设计验证
- 新模块或新服务接入前的接口与边界审查
- 技术选型或架构决策需要第二意见

## 输入格式

| 输入示例 | 说明 |
|----------|------|
| `@architecture-review` | 审查当前项目/变更的架构 |
| `@architecture-review 目标：模块 X 与 Y 的边界` | 聚焦特定模块 |
| `@architecture-review 重构方案：xxx` | 评审给定重构方案 |

## 审查维度

### 1. 模块边界

- [ ] 职责是否单一、边界是否清晰
- [ ] 依赖方向是否合理（高层不依赖底层细节）
- [ ] 是否存在循环依赖
- [ ] 跨模块接口是否稳定、易演进

### 2. 系统设计

- [ ] 数据流与状态归属是否合理
- [ ] 错误处理与降级策略
- [ ] 可观测性（日志、监控、追踪）
- [ ] 配置与环境分离

### 3. 可扩展性

- [ ] 新增能力时改动范围是否可控
- [ ] 是否存在单点瓶颈
- [ ] 水平/垂直扩展路径是否清晰

### 4. 重构方向

- [ ] 重构目标是否明确
- [ ] 分步策略是否可执行
- [ ] 风险与回滚预案
- [ ] 对现有功能的影响范围

## 输出格式

使用标签（按规则不使用 emoji）：

- **[Critical]**: 架构风险，必须处理
- **[Suggestion]**: 建议改进
- **[Nice to have]**: 可选优化

```markdown
# Architecture Review: [范围/主题]
## 摘要
[1–2 句概述]
## Critical
- [问题描述与影响]
## Suggestions
- [建议]
## Nice to have
- [可选改进]
## 重构建议（如适用）
[分步或优先级建议]
```

## 项目类型

针对 React Native、React、Vue、Node、微信小程序等，需关注：

- **React/React Native**: 组件层级、状态位置、Context 使用、跨端共享逻辑
- **Vue**: 组件通信、Store 设计、组合式逻辑复用
- **Node**: 分层、中间件顺序、依赖注入
- **微信小程序**: 页面/组件职责、跨页面状态、分包策略

## 推荐模型

- 日常架构评审：`GPT-5.4`
- 高风险、跨系统设计：`Claude Opus 4.6 (Thinking)`
