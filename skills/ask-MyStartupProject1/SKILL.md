# ask-MyStartupProject1

## 目的
本技能是 `D:/work/MyStartupProject1` 项目的默认入口。
用于帮助用户：
- 选择值得投入的产品方向
- 避免重蹈上一个项目用户采用率偏低的覆辙
- 在大量投入实现之前验证需求
- 决定下一步应使用的 BMad 角色或工作流
- 在项目目录下用中文文档沉淀可复用的项目决策

## 稳定背景
除非用户明确修改，否则默认以下背景：
- 用户为独立开发者，前端经验丰富，覆盖 React、React Native、Vue 2、Vue 3、TypeScript、JavaScript、HTML、CSS、小程序、Flutter、iOS、Android。
- 希望产品能同时获得美元与人民币收入。
- 偏好前期成本低、建设周期短、需求面大、留存扎实、付费转化健康，并具备被动收入潜力。
- 当前阶段多为调研、想法验证、产品定义与规划，而非立即写代码。
- 默认回复语言为简体中文。
- 涉及代码时，代码注释保持英文。

## 当前工作假设
当前主导假设为：
- 探索面向患者的手部或手指创伤居家康复类产品
- 侧重执行、记录、提醒、风险提示与复诊/随访准备
- 避免将产品定位为医学诊断或替代医生
重要说明：
- 将其视为当前优先探索方向，而非固定承诺。
- 若用户提出更有力的方向，应客观评估，而非强行绑定康复设想。

## 相关上下文来源
仅读取当前任务所需的最少上下文。
常见来源：
- 项目根目录：`D:/work/MyStartupProject1`
- 当前策略笔记：`D:/work/MyStartupProject1/项目方向与BMad前期调研建议.md`
除非用户明确要求对比，否则不要引入无关旧项目。

## 路由规则
按请求匹配最合适的 BMad 角色或工作流：

### 1. 想法验证与问题定义
当用户关注以下主题时，使用 `bmad-agent-analyst`：
- 市场调研
- 竞品分析
- 目标用户
- 痛点
- 价值主张
- 某个想法是否值得做
- 该选哪个方向

### 2. 市场格局与商业信号
当用户需要以下信息时，使用 `bmad-market-research`：
- 市场规模
- 竞品格局
- 变现模式
- 定价对比
- 中国 vs 全球机会对比

### 3. 领域理解
当用户需要以下能力时，使用 `bmad-domain-research`：
- 医疗或康复领域认知
- 患者旅程分析
- 诊所、治疗师、患者或照护者相关工作流调研
- 术语或行业实践澄清

### 4. 产品定义
当用户希望以下产出时，使用 `bmad-product-brief`：
- 产品 Brief
- 更清晰的产品概念
- 目标用户与核心价值归纳
- 界定 MVP 边界

### 5. 路线图与优先级
当用户提出以下需求时，使用 `bmad-agent-pm`：
- 路线图规划
- 功能优先级
- 版本规划
- 里程碑规划
- 需求拆解

### 6. 架构与实现
当用户提出以下需求时，使用 `bmad-agent-architect` 或 `bmad-agent-dev`：
- 技术架构
- 技术栈决策
- 实现规划
- 编码或重构

默认规则：
- 若任务仍是「做什么、为什么做」，优先路由到偏分析师的工作流。
- 产品方向仍不清晰时，不要直接进入实现。

## 执行工作流
除非用户明确要求更窄的范围，否则按以下顺序：
1. 识别任务类型  
   - 将请求归类为调研、产品定义、规划或实现
2. 仅收集最少必要上下文  
   - 优先使用已有项目文档，再扩展  
   - 避免加载无关文件
3. 尽早澄清模糊点  
   - 若多个想法并存，帮助用户选定一个焦点  
   - 若范围过宽，每次只收敛到一个决策
4. 按以下顺序作答  
   - 结论  
   - 推理依据  
   - 建议的下一步 BMad 角色或工作流  
   - 是否应写入项目文档
5. 在适当时沉淀重要决策  
   - 若用户要求总结或归档，更新或新建项目文档  
   - 优先更新已有主题文档，避免拆成大量小文件

## 输出约定
当用户要求持久化结论时，使用中文，并写入 `D:/work/MyStartupProject1`。
首选文档策略：
- 若已有与主题匹配的文档，则更新该文档
- 否则新建聚焦文档，文件名使用清晰的中文
首选文档类型：
- 项目方向与定位
- 市场调研摘要
- 竞品分析
- 产品 Brief
- 路线图或里程碑计划
对文档的期望：
- 以决策质量为先，而非篇幅
- 记录结论、为何重要、曾考虑的备选方案与建议的下一步
- 避免堆砌低价值的聊天式流水账

## 边界
通过以下约束保持技能稳定：
- 不要混入已放弃项目的指示。
- 不要假定当前康复方向已是终局。
- 不要把医学相关建议表述为确诊或治疗上的确定性结论。
- 除非用户明确要求，不要自动运行应用、测试或浏览器自动化。
- 不要为小问题批量产出多余规划文档。
- 不要在未验证用户需求之前过度设计产品。

## 质量标准

在本技能下，一份好的回应应：

- 帮助用户做出一项具体的产品决策
- 将该决策映射到合适的 BMad 角色
- 保留战略上的回旋空间
- 扎根于用户需求、变现路径与独立开发者约束

- 「帮我做市场调研」
- 「帮我写产品 Brief」
- 「给 MyStartupProject1 做路线图」
