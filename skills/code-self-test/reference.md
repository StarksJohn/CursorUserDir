# Code Self Test Reference

只读取与当前精确范围、项目规则命中的章节。本文件补充 `SKILL.md`，不替代自测协议和证据门禁。

## 失败路径目录

对每个变更函数、组件、接口处理函数或原生回调，先列出可到达分支，再问「这条路径的实际结果是什么」。下列未处理且可到达时，优先记为 BUG：

- 空值、空字符串、空数组、缺字段、错误类型。
- 加载中再次进入、请求失败、超时、HTTP 非 2xx、业务 code 非成功。
- 重复点击、重复提交、并发两次进入同一异步。
- `await` 之后组件已卸载，或页面已返回。
- 权限拒绝、登录过期、token 刷新失败。
- 仅 iOS 或仅 Android 的字段被共享逻辑直接使用。
- 监听、定时器、订阅、文件句柄、连接未清理。
- 列表 key 不稳定、index 当 key 导致串状态。
- 表单提交时键盘挡住主按钮，或焦点陷阱。
- 错误态无法重试，空态与失败态无法区分。

走得通、有具体坏结果才报 BUG。走不通的理论路径删除。

## 按技术栈找 BUG

只执行命中当前范围的检查。

### TypeScript / React / Next.js

- 新增命名函数、组件、Hook 的参数和返回值要明确；async 使用 `Promise<...>`；禁止新增或扩大 `any`。公共契约上的 `any` 掩盖真实类型时记为 BUG。
- 当前范围新增的类型错误、`@deprecated` 调用（如 TS6385/TS6387）记为 BUG。普通 `tsc` 不显示 suggestion diagnostics 时，能用项目本地 Compiler API 或 Language Service 就补这一层；不能补则标记覆盖阻塞。
- Hook 依赖、旧闭包、渲染期副作用、缺少 cleanup、异步竞态。
- Next.js：server/client 边界、hydration、错误的缓存或环境变量泄漏到客户端。
- UI 不可操作、关键断点溢出、无法完成主路径时记为 BUG；可选 memo 不算 BUG。

### Vue 2 / Vue 3 / JavaScript

- 先确认 Vue 版本。Vue 2：新增属性响应式、`this`、生命周期清理。Vue 3：解构丢响应式、watch 清理、只读 props。
- 漏 `await`、未处理 Promise、`forEach(async)`、弱比较导致的错误分支。

### React Native / 原生

- 共享逻辑使用 `iOS ONLY` / `ANDROID ONLY` 字段时，必须有 `Platform.OS` 分支和另一端 fallback。
- 导航恢复、权限、前后台、键盘与 Safe Area、长列表/图片内存、桥接契约。
- iOS：retain cycle、主线程 UI、强制解包。Android：生命周期、协程取消、主线程 IO。
- 未做设备验证时分别标注 Android/iOS 未验证，不能假设两端一致。

### API / Node / 数据 / 隐私

- 输入未校验、鉴权缺口、注入、XSS、SSRF、路径穿越、开放重定向、日志泄密。
- 未处理 rejection、事务不完整、句柄不关、非幂等重复提交。
- schema/migration 只做只读检查，不执行写入。
- 遵循项目 `AGENTS.md` 的医疗文案、隐私和生产写入规则。

### Flutter / 小程序 / HTML / 配置

- Flutter：dispose、`mounted`、空安全、三态（loading/error/empty）。
- 小程序：`setData`、`wx:key`、授权、请求域名。
- HTML/CSS：关键键盘操作、label/alt、溢出导致主操作不可达。
- 配置变更：目标环境污染、秘密进仓库、锁文件与产物不一致。

## 性能与体验优化目录

只在 BUG 狩猎之后使用。每条必须能回答「当前成本是什么」和「怎么优化」。

优先看这些，因为它们同时影响性能和用户体验：

- 无关 state 变化导致大子树重渲染；列表项内联对象/函数；不稳定 `key`。
- 长列表未窗口化，或窗口化后仍在主线程做重计算。
- 图片无尺寸、无缓存策略、重复解码；RN 未走项目已有 FastImage 或等价方案。
- 启动或进页时串行等待可并行的数据；重复打同一 API；缺缓存或缓存键错误。
- JS 线程上做重 JSON/排序/正则；滚动时同步布局。
- 导航慢、返回丢状态、提交无 pending、失败无重试。
- 键盘遮挡输入或主按钮；Safe Area 裁切可点区域。
- 空态、错误态、骨架屏缺失，用户以为卡住。
- 无障碍：可点区域过小、对比不足导致无法完成操作（这是体验，不是风格）。

不要报：变量改名、注释风格、与热路径无关的抽象拆分、未测量的「加上 memo 总没坏处」。

## 自测命令选择

1. 先读 `package.json` / 项目 `AGENTS.md` 里的 test、typecheck、lint 脚本。
2. 只跑与 changed files 相关的最小命令。
3. 不安装依赖，不改 lockfile，不发明第二套工具链。
4. 类型检查必须用项目 `tsconfig`；禁止 `tsc path/to/file.ts` 脱离项目配置制造假结论。
5. 测试失败要能指向当前范围 hunk。不能隔离时写入验证边界，不要把基线失败算成当前 BUG。

## 「怎么解决」最低标准

BUG 的修复说明至少包含：

1. 根因一句话（哪条路径、哪个值、哪个时机）。
2. 最小代码骨架或 before/after，能贴进当前文件。
3. 需要同步的调用者、类型、测试或 i18n。
4. 修复后如何重复 L2/L3 自测。
5. 若无法唯一确定修复，写明缺失事实、最可能方向和待确认项；仍要给接近可用的代码骨架。

## 「怎么优化」最低标准

优化说明至少包含：

1. 当前成本：多一次渲染、多一次请求、主线程耗时、用户多等一步或看不懂状态。
2. 改动点：文件和关键表达式。
3. 最小做法：代码骨架。
4. 验证：具体操作或已有性能测试/Profiler 指标。
5. 风险：是否改变语义、是否只对某平台有效。

## 结论分支

```
自测完成
├─ 有确认 BUG → 必须输出 BUG + 怎么解决；随后只保留高价值性能/体验优化
└─ 无确认 BUG → 必须输出可优化内容 + 怎么优化；摘要写明未发现当前范围引入的 BUG
```
